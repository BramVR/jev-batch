# Formal verification of jev.py and demo redaction contracts

`check.py` enumerates every combination in a stated finite domain and runs the real `jev.main` on each, in-process, with `urllib.request.urlopen` replaced by a scripted responder and backoff jitter pinned. For the demo it runs the real `redact`, `redact_records`, `prepare_sample`, and `main` from `scripts/demo_sessions.py`, with `ROOT` moved to a temp dir and the inner `jev.py` subprocess replaced by a recorder that encodes and decodes the pipe as ASCII unless the call pins UTF-8. No network, no deps. It reports each property in the code's terms and flags any change in known findings.

Tool choice. Python has no practical code-level verifier for this program: CrossHair-style symbolic execution stalls in `json` and `urllib`. Bounded exhaustive enumeration over hand-picked equivalence classes drives the real code instead of a model of it. The only concurrency is `batch`'s sliding window: one reader thread, a `ThreadPoolExecutor` of `--concurrency` workers, and no state shared between workers except the stop event. The check runs the real threads and asserts invariants on what each request observes (flushed line count, requests in flight), and drives every completion order of four lines with timed responses. That covers the windows exercised, not every interleaving; a TLA+ model was judged not worth it for one deque and one event. The pass covers the enumerated domain, not every string.

## Run

```sh
python3 .claude/skills/formal-verify-jev/check.py              # all properties, batch depth 3, ~45s
python3 .claude/skills/formal-verify-jev/check.py --mutants    # also prove each property can fail, ~6min
python3 .claude/skills/formal-verify-jev/check.py --only retry  # retry policy alone, <1s
python3 .claude/skills/formal-verify-jev/check.py --only redaction   # demo redaction only, <1s
python3 .claude/skills/formal-verify-jev/check.py --only cache # cache properties only, ~12s
python3 .claude/skills/formal-verify-jev/check.py --only questions   # question-file versioning only, <1s
python3 .claude/skills/formal-verify-jev/check.py --only eval  # eval properties only, ~8s
python3 .claude/skills/formal-verify-jev/check.py --only summarize   # summarize only, ~1s
python3 .claude/skills/formal-verify-jev/check.py --only chunk     # chunking only, ~5s
python3 .claude/skills/formal-verify-jev/check.py --depth 4 --only batch   # deeper batch, several minutes
python3 .claude/skills/formal-verify-jev/check.py --stale      # covered files changed since the last sync?
```

It needs a Python that `jev.py`'s `MIN_PYTHON` accepts. On an older one, `load()` runs that guard and `check.py` exits with `jev.py`'s version message.

Each mutant reruns only the section that owns its property, by prefix in `SECTIONS` (`batch-`, `numbers-`, `questions-`, `cache-`, `eval-`, `redact-` and `demo-` for redaction; the rest are `requests`). A property checked outside its prefix's section is listed in `PROPERTY_SECTIONS`, such as `dry-run-ignores-cache` in `cache`; add one there when you add such a property, or its mutant runs the wrong section and is reported `MISSED`.

Exit 0 and `PASS` means no new violations, every known finding still reproduces, and, with `--mutants`, every mutant was caught.

## Does my change touch this?

Covered files: `jev.py`, all of `Backend` (including `price` and `PRICES`), `api_key`, `Cache`, `read_json`, `valid_response`, `load_questions`, `request_payload`, `uses_images`, `request_body`, `prepare`, `retry_after_seconds`, `send`, `backoff_seconds`, `post`, `respond`, `classify`, `batch`, `summarize`, `run_summarize`, `estimate`, `estimate_tokens`, `dry_run_report`, `utf8_tokens`, `chunk_capacity`, `split_text`, `check_chunk_questions`, `chunk_plan`, `choice_probabilities`, `mean_choice`, `run_chunks`, `estimate_chunked`, `id_key`, `jsonl_records`, `evaluate`, `main`; `scripts/demo_sessions.py`, all of `REDACTION_RULES`, `redact`, `redact_records`, `prepare_sample`, `read_jsonl`, `main`. Sync point: `SYNC_BLOBS` in `check.py`, the git blob id of each covered file as last checked. It records content, not a commit, so rebases and squash merges keep it valid. Run `--stale`. A `CHANGED` file means run the full check with `--mutants`. `--stale` also prints the commit that last held the synced blob, when history still has it, for the diff to read.

## Properties

Each property is one sentence of promise and one of harm.

- `batch-prefix`. Batch stdout is exactly `{"id": id_i, ...response_i}` for every line before the first failing line, in order, at every retry limit and concurrency bound in scope. Otherwise a resumed batch silently loses or duplicates records.
- `batch-attempts`. Every line up to and including the first failing one was sent exactly as often as the retry policy says: once for a success, twice for a line that fails once then succeeds, `retries + 1` times for a transient failure, once for a permanent failure, never for a locally invalid line. Otherwise records are double-billed or the retry limit is not a limit.
- `batch-no-send-past-window`. After the first failing line k, a later line is sent only if it lies within `concurrency - 1` lines of k, before any locally invalid line, and within its own attempt limit. At concurrency 1 nothing after k is sent. Otherwise requests go out after the user was told the batch stopped.
- `batch-window`. Line p's first request sees at least `p - concurrency + 1` and at most `p` output lines already flushed. At concurrency 1 that is exactly "line p-1 flushed before line p is sent". Otherwise a crash loses paid-for results, or buffered output grows past the bound.
- `batch-in-flight-bound`. Requests in flight at once never exceed `--concurrency`. `batch-order-under-concurrency`: for every completion order of four lines at every bound 1 to 4, output is in input order. Otherwise the backend's rate limit is overrun or results are misattributed.
- `batch-exit`. Exit 0 with empty stderr, or exit 1 with one line `jev: batch stopped at line N; ...` naming the first failing line, with `gave up after N attempts` for retried failures. Otherwise users resume from the wrong line.
- `batch-blames-right-party`. When line N fails after it was sent, stderr never says `invalid JSON record`, and a response that is not UTF-8, not JSON, or holds nonfinite numbers reads exactly `jev: batch stopped at line N; System One returned invalid JSON`. Otherwise users edit a correct input line to fix an API failure.
- `batch-no-body-leak` and `retry-no-body-leak`. HTTP error and unparseable response bodies never reach stdout or stderr. Otherwise private API text leaks into logs.
- `retry-attempts`. A request is sent `retries + 1` times exactly when it failed with HTTP 429, any 5xx, a network error or timeout, or an error body containing exactly `Endpoint is unavailable` on a status other than 401, 403, or 422; otherwise once. `retry-exit` pins the matching `gave up after` or `not retryable` message. Otherwise auth failures get retried or outages fail on the first blip.
- `retry-backoff-schedule`. With jitter pinned to its upper bound, the waits are `min(30, 0.5 * 2**n)`, and a valid `Retry-After` (integer seconds, or an HTTP date in the past or future) replaces each wait, capped at 30. Otherwise the CLI hammers a rate-limited backend or stalls for minutes.
- `credential-read-only-for-typesafe` and `auth-only-to-typesafe`. Credentials are read, and `Authorization` is sent, only when urllib's own parse of the endpoint is `https` to `api.typesafe.ai`. Otherwise a TypeSafe key goes to another host. The `BASE_URLS` with a tab, newline, trailing space, DEL, or non-ASCII path, where `urlsplit` and urllib disagree or `http.client` cannot send, must exit 1 before any credential read (`request-clean-exit`), and their dry run must reject them the same way instead of pricing them (`dry-run-validates-like-send`, `dry-run-cost`).
- `auth-sent-to-typesafe-when-keyed`. With a key and that exact target, `Authorization: Bearer <key>` is sent. Otherwise TypeSafe users get silent 401s.
- `request-body`, `request-endpoint`, `request-method`, `request-timeout`, `request-content-type`, `request-user-agent`. The single POST goes to `base.rstrip("/") + "/systemone"` with body exactly `{model, state, questions}` plus `assets` when the record has them, and extra record fields are never sent. Otherwise private fields leak or the API rejects the call.
- `images-header-iff-images` and `box-rejected-locally-on-free`. `TypeSafe-Danger-Zone-Images: true` is sent exactly when there are assets or a Box question, and free OpenCode or Jev 1.13 rejects them before any request. Otherwise image data reaches a text-only backend.
- `numbers-passthrough-exact`. Every finite number in the response, including `5e-324`, `0.30000000000000004`, `-0.0`, `2**64`, comes out with the same type and float bits, and keys keep their order. `numbers-nonfinite-rejected`: `NaN`, `Infinity`, and overflowing literals like `1e999` anywhere in a response mean exit 1 and no stdout. Otherwise downstream code reads altered probabilities or invalid JSON.
- `questions-accept-iff-valid`. A question file is accepted exactly when it is a nonempty mapping of supported question types, bare or inside `{"schema_version": 1, "questions": ...}` with no other keys, where the version is the integer `1` (not `True`, `1.0`, or `"1"`). Otherwise unknown versions run as if supported, or valid legacy files break.
- `questions-unwrap-exact`. An accepted file sends exactly one request whose body keys are `model`, `state`, `questions`, and whose `questions` equals the unwrapped mapping, key order included. Otherwise wrapper metadata reaches the API or the two forms diverge.
- `questions-reject-before-network`, `questions-reject-message`, `questions-reject-no-echo`. A rejected file exits 1 with no request, one `jev: ` line that is not the generic read error, and none of the file's content. Otherwise bad files cost a request, users get no actionable error, or private question text reaches logs. The same files also drive `summarize` (empty input, `--question zz`): a file is accepted exactly when it is valid, and an accepted one prints `records: 0` with no request (`questions-summarize-offline`). Otherwise summarize silently ignores a version-1 file or accepts one `classify` rejects.
- `questions-eval-same-loader`. `eval --question c` over every file in `question_documents()` scores exactly when that file is accepted and holds Choice `c` with criteria, with labels in criteria order, and otherwise exits 1 with one non-generic `jev: ` line that echoes nothing; no request or credential read either way. Otherwise eval and the request path disagree on which question files are valid.
- `redact-no-fixture-survives`. Each planted secret, in every context and nesting shape, leaves no trace of its sensitive part. Otherwise the demo sends it.
- `redact-counts-exact`. Each planted secret adds exactly one hit to its own rule. Otherwise the summary misreports what was removed, or rules overlap and double-count.
- `redact-idempotent`. A second pass changes nothing and counts nothing. Otherwise re-redacting at send corrupts placeholders and inflates counts.
- `redact-structure-kept` and `redact-id-kept`. Keys, key order, non-string values, and record IDs stay unchanged, in `redact_records` and in the outgoing batch. Otherwise results cannot be joined back to sessions.
- `redact-metadata-no-leak`. Redaction metadata, extra record fields, stdout, stderr, and `summary.json` never contain a planted value. Otherwise the diagnostics leak what redaction removed.
- `redact-benign-unchanged`. Ordinary text near the patterns, such as `the token is useful`, URL paths with `/home/`, and short `sk-` words, is left alone. Otherwise the classifier sees noise.
- `redact-before-cap`. A secret straddling the 4,000-character message cap at every cut point leaves no 6-character run of its sensitive part in the prepared sample. Otherwise truncation leaves a partial secret that no rule matches.
- `redact-counts-kept`. Prepare counts equal the complete placeholders in the saved excerpts: one hit for a secret well inside the cap, none for one wholly past it, and none for a placeholder the cap cuts. Otherwise the summary reports redactions the saved sample does not contain.
- `demo-send-redacts-outgoing` and `demo-opt-out-sends-raw`. `--send` redacts the outgoing copy of a raw saved sample, and `--send --no-redact` sends it as is. Otherwise old samples leak or the opt-out is silently ignored.
- `demo-send-caches`. Every `--send`, redacted or `--no-redact`, runs `jev.py batch` with `--cache <root>/.private/demo/cache`, so the cache keys on the outgoing copy. Otherwise a rerun after a partial send bills finished records again.
- `demo-send-utf8`. Non-ASCII sample text reaches `jev.py batch` unchanged when everything not pinned to UTF-8 is modeled as ASCII: the parent's pipe, and the child's stdio unless `stdio-utf8` holds for the `jev.py` under check. Otherwise sends fail or mangle text on a non-UTF-8 locale.
- `demo-send-sample-unchanged` and `demo-send-gates`. `--send` never rewrites or resamples `sample.jsonl`, and it sends exactly when `1 <= --limit <= 20` and the sample exists with `1..limit` records, else exit 2 and no send. Otherwise approval and sample-size limits are bypassed.
- `demo-send-summarize`. After `--send`, `summary.json` takes its category counts, first three example IDs, and confidence classes from `jev.py summarize` over the results, which runs in-process here behind the same modeled pipe and reads the same examples file, and its UTF-8 pin is exercised by non-ASCII record IDs. Otherwise the demo reports counts the results do not support, or crashes on a non-UTF-8 locale (`demo-send-clean-exit`).
- `cache-hit-iff-same-request`. With `--cache`, a second run sends zero requests exactly when its endpoint and request body (model, state, questions in order, assets) equal the first run's. Record IDs and extra fields never split a hit; any other difference misses. Otherwise stale answers come back for a changed request, or finished work is billed again.
- `cache-output-current-id`. A hit prints `{"id": <current id>, ...<stored response>}`, byte-equal to the response first stored. Otherwise results carry the wrong record ID or altered answers.
- `cache-hit-across-question-file-forms`. A version-1 question file and its legacy mapping share cache entries in both run orders, since only the unwrapped mapping is sent. Otherwise wrapping a file re-bills every finished record.
- `cache-never-stores-failure`. At the default `--retries 3`, HTTP errors, connection failures, and timeouts that exhaust their retries, auth failures that never retry, and invalid, colliding, or nonfinite responses leave no entry, and the next run sends again. Otherwise a failure is replayed forever.
- `cache-stores-after-retry`. A request that fails once with a retryable error and then succeeds is stored, and the next run sends nothing. Otherwise a flaky backend re-bills every record that needed a retry.
- `cache-duplicate-within-run`. Two lines with identical request bodies in one batch send one request at `--concurrency 1`, since the second hits the first's entry, and at most two above it, since both can be in flight before either stores. Output keeps input order with current IDs. Otherwise sequential runs re-bill duplicates, or concurrency breaks the cache.
- `cache-corrupt-refetch` and `cache-corrupt-rewritten`. An empty, truncated, non-UTF-8, non-object, wrong-version, wrong-key, or invalid-response entry is a miss: exit 0, one request, fresh output, and the next run hits the rewritten entry. Otherwise one bad file breaks or poisons every later run.
- `cache-resume-sends-only-missing` and `cache-resume-output`. Over every batch sequence of `LINE_KINDS` up to depth 2, an interrupted run at the default `--retries 3` sends each line exactly as often as the retry policy says, and an all-success rerun sends one request for each line from the first failure up to the first locally invalid line and none for lines already stored. Both print the merged prefix a reference model predicts. Lines are keyed by position, so retried requests count against their own line. Otherwise resuming re-bills finished records or drops them.
- `eval-offline`. `eval` sends no request and never calls `api_key`, even with `JEV_BASE_URL` at TypeSafe and a key in the env. Otherwise scoring saved results leaks data or credentials.
- `eval-report`. For every labels/predictions pair in the domain, the report equals `eval_oracle`, a plain-loop restatement of README: denominators, `correct`, `accuracy`, `confusion[label][choice]`, and ten low-inclusive calibration buckets with `1.0` in the top one, compared bit for bit. Otherwise users trust a wrong accuracy or calibration.
- `eval-errors`. An empty labels file, duplicate IDs in either file, a label outside criteria keys, malformed or blank lines, and a missing or non-Choice question exit 1 with no stdout and one `jev: ...` line naming the file and line. Otherwise ambiguous joins produce silent wrong metrics.
- `eval-inputs-unchanged`. The labels file bytes are identical after every eval run. Otherwise hand labels get corrupted.
- `dry-run-no-network-no-credentials`. `--dry-run` never calls `urlopen` or `api_key`, for every request case and batch sequence. Otherwise pricing a run reads a key or bills it.
- `dry-run-validates-like-send`. Dry-run `classify` exits with the same code and stderr as a real send of the same case, except the send's missing-key failure, which dry run skips by contract. Otherwise a priced run fails once sent.
- `dry-run-batch-exit` and `dry-run-batch-report`. Batch dry run stops at the first locally invalid line with the usual `batch stopped at line N` and no stdout. Network-stage lines count as valid. Otherwise it prints one report with every line's `line` and `id` in order. Otherwise users price a run that cannot start, or a different set of records.
- `dry-run-measures-sent-bytes`. A dry run's `request_bytes` equals the length of the body the real send of the same case POSTed, `assets` included. Otherwise the estimate measures a request that is never sent, as it did for Unicode before the fix.
- `dry-run-tokens` and `dry-run-total-is-sum`. Each record's estimate is the README rule (`ceil(bytes / 4)` over the ASCII-escaped UTF-8 JSON body without `assets`), and the total is the sum of the rows. Otherwise the estimate drifts from what the README promises.
- `dry-run-questions-like-send`. For `classify` and `batch` (summarize and eval do not declare `--dry-run`), for every question document, legacy or version 1, valid or not, `--dry-run` gives the same exit code and stderr as a send, and an accepted file's row reports the sent body's byte length and a question estimate over the unwrapped mapping. Otherwise a wrapped file is priced with its `schema_version` metadata, or a file the send rejects gets a price.
- `dry-run-ignores-cache`. For every cache config, `--dry-run --cache DIR` creates no directory on a cold cache, leaves a warm cache byte-identical, sends nothing, and prints the same report as a dry run without `--cache`. Otherwise pricing a run writes or trusts cache entries, or the estimate depends on cache state the README says it ignores.
- `dry-run-cost`. Price, status, and cost match the README table, restated in `DRY_RUN_PRICES`: free OpenCode `jev-1.13-free` costs `"0"`, HTTPS TypeSafe `jev-1.14.0` costs `0.042 × tokens / 1e6` exactly as a `Decimal`, and any other host, model, scheme, or a record with assets gives a `null` cost. Otherwise users see an invented price.
- `summarize-offline`. `summarize` sends no request and reads no credentials, even with a TypeSafe `JEV_BASE_URL` and `TYPESAFE_API_KEY` set. Otherwise saved private results reach an API or a key is read for no reason.
- `summarize-counts`, `summarize-examples`, `summarize-denominator`. `records` is every input line, `counts` covers each once in `--questions` criteria order then first-seen order, `examples` holds the first three IDs per label unchanged, and bins plus `missing`, `malformed`, `out_of_range` sum to `records`. Otherwise demo counts silently drop or double-count sessions.
- `summarize-bins` and `summarize-confidence-classes`. A number in [0, 1] lands in the bin whose lower edge `i / 10` it reaches, 1 in `0.9-1.0`; absent is `missing`, a non-number or boolean is `malformed`, and outside [0, 1] is `out_of_range`. Otherwise the histogram misreports confidence at the edges.
- `summarize-diagnostics` and `summarize-exit`. Each malformed or out-of-range value has one `line N: ...` diagnostic, mirrored as `jev: ...` on stderr, with exit 0. `summarize-stop-line`: an invalid JSON line or a line without `id`, else the first non-Choice answer, exits 1 naming that line with no stdout. With no `--question` and no question name in the input, `summarize-selection` expects exit 1 asking for one. Otherwise users fix the wrong line.
- `summarize-choice-only`. For each question spec `load_questions` accepts, legacy and version 1, `summarize --question q --questions FILE` on empty input prints zero counts in criteria order exactly when the spec is a choice with mapping criteria; any other spec exits 1 with `jev: summarize supports Choice questions only; 'q' is not one`, no stdout, and no request. `run_summarize` passes `summarize` only `load_questions` output, so `summarize` reads `spec["type"]` with no dict check. Otherwise a Score, Noul, or Box question, or a list of criteria, is summarized as Choice labels.
- `stdio-utf8`. `summarize` with stdin and stdout as ASCII-locale text streams reads a UTF-8 line holding `é` and U+2028 and writes the summary as UTF-8. Otherwise every caller must set `PYTHONIOENCODING`, and UTF-8 JSONL fails on a non-UTF-8 locale.
- `flags-scoped`. Read from `jev.build_parser()`: every flag some command declares exits 2 (`unrecognized arguments`) on each command that does not declare it, with no stdout, request, credential read, or file written; `eval` and `summarize` declare none of the sending flags `classify` and `batch` share except `--questions`; abbreviations are off, so `classify --question` is not `--questions`. Otherwise a command silently ignores a flag the user expected to matter.
- `chunk-request-body`, `chunk-bounded`, `chunk-cover`, `chunk-greedy`. With `--chunk-tokens`, every request is `{model, state, questions}` with string state of at most `state_capacity` UTF-8 bytes. The states concatenate to the original with no empty or overlapping piece, and each chunk but the last is full, so adding the next character would exceed capacity. Otherwise requests exceed Jev's limit, text is lost or duplicated, or a record costs needless requests.
- `chunk-small-unchanged`. State within capacity, empty included, gives one request and stdout byte-identical to the same run without the flag. Otherwise opting in changes results for inputs that never needed chunking.
- `chunk-metadata` and `chunk-responses-verbatim`. A chunked record keeps the input `id`, `chunking.count`, contiguous `start`/`end` character offsets that slice out exactly the sent states, and every chunk response bit for bit. Otherwise the aggregate cannot be audited.
- `chunk-mean-exact`, `chunk-argmax-tiebreak`, `chunk-confidence`, `chunk-one-post-per-chunk`. Each label's probability is the correctly rounded equal-weight mean, checked against `fractions.Fraction`, in criteria order. The choice is the first criteria label with the highest mean, and `confidence` is the chosen label's mean. Otherwise users read a different aggregate than README documents.
- `chunk-failure-closed` and `chunk-no-body-leak`. A failed chunk (HTTP 500 or 400, timeout, invalid or nonfinite JSON, missing answer, wrong or boolean probability labels) exits 1 with `chunk i/n: `, sends no later chunk of that record, prints no aggregate, and keeps the batch prefix, at `--concurrency` 1 and 2. Otherwise a bad chunk is billed onward, or a partial aggregate passes as complete.
- `chunk-guards`. Non-Choice questions, criteria that are not a nonempty object, object or array state, assets, and budgets outside 1..32000, non-integer, or too small for question overhead exit 1 or 2 with no request. Otherwise unsupported input is silently truncated or misaggregated.
- `chunk-cache-resume` and `chunk-cache-reuse`. With `--cache`, after a chunk fails in any `CHUNK_FAILURES` way, an all-success rerun sends exactly the chunks from the failed one on, and a third identical run sends nothing and prints the same record. Otherwise a label-rejected answer is cached and replayed forever, or a resumed record bills chunks it already paid for.
- `chunk-retry-resends-only-that-chunk`. With `--retries 1`, a transient failure (HTTP 500 or timeout) at any of 3 chunks is retried once and the record succeeds, resending only that chunk. Otherwise long records fail on blips a plain record survives, or retries resend chunks already answered.
- `chunk-dry-run`. `batch --dry-run --chunk-tokens` sends nothing, reads no credentials, and reports `request_bytes` equal to the summed bodies a real chunked send POSTs, with `chunks` exactly when the record splits. Otherwise users are quoted a price for requests they will not send.
- `*-clean-exit`. No input in scope escapes `main`, `redact`, or the demo's `main` as an uncaught exception.

Domain and bounds, all in `check.py`: `LINE_KINDS` (20 line outcomes) at every sequence length up to `--depth` for concurrency 1 with retries 0 and 2, and up to length 2 for concurrency 2 and 3 (`BATCH_MODES`); every permutation of four completion delays at concurrency 1 to 4; `STATUSES` x `ERROR_BODIES` x `RETRY_AFTER` plus `NETWORK_ERRORS`, at retries 0, 1, and 3; `BASE_URLS` x `MODELS` x `QUESTION_SETS` x `RECORDS` x key present or absent; `FINITE` + `NONFINITE` in three response slots for both commands; `question_documents()` (`MAPPINGS` bare and wrapped, reordered, or with an extra key under every `VERSIONS` value, plus missing-key wrappers and `RAW_FILES` such as invalid JSON, non-UTF-8, nonfinite numbers, and 100k-deep nesting) for `classify`, `batch`, `eval`, and `summarize`; every request case and batch sequence once more with `--dry-run`; for eval, every assignment over `EVAL_IDS` (`"x"`, `1`) of label state (none, `a`, `b`) and prediction state (none, or `EVAL_CHOICES` x `EVAL_CONFIDENCES`, covering unknown and missing choices, bin edges, out-of-range, bool, and string confidences), with and without an extra prediction `"1"` that must not join to `1`, plus the `EVAL_ERRORS` table; `SECRETS` (20 look-alikes covering every rule) and `BENIGN` (13 near misses) x `CONTEXTS` (7) x `SHAPES` (4 nestings); every cut point of every secret at the cap, plus the secret wholly past and wholly inside it; `--limit` in {-1, 0, 1, 2, 20, 21} x sample missing or 0, 1, 2, 20, 21 records; every ordered pair from `CACHE_BASES` x `CACHE_MODELS` x `CACHE_QUESTIONS` x `CACHE_RECORDS` (90 configs), each `CACHE_QUESTIONS` mapping bare then wrapped and wrapped then bare, every network failure kind, every entry in `CORRUPTIONS`, and cache resume over `LINE_KINDS` to depth 2. The cache oracle `request_identity` derives identity from the README contract, not from `Cache.path`. Each cache case uses a fresh directory under the checker's temp dir; summarize over `SUMMARY_KINDS` (two labels x 18 `CONFIDENCES`, plus bad JSON, missing id, and a Score answer) at every sequence length up to 2, plus every four-record sequence over `LONG_KINDS` so the three-ID example cap binds, each with `--question` and seeding, with `--question` and no `--questions`, with no `--question` plus a two-question file so the name is inferred from the input and labels still seed, and with `--question` plus that file as a version-1 document; for chunking, every string over `CHUNK_ALPHABET` (1 to 4 byte code points) up to `--depth`+1 characters at each of `CHUNK_CAPACITIES`, per-chunk probability pairs from `GRID` for 2 and 3 chunks under both criteria orders (including 0.5 plus or minus one ulp), `CHUNK_FAILURES` at each of 3 chunks for classify and for batch at concurrency 1 and 2, the same failures under `--cache` with a resume and a repeat run, transient failures under `--retries 1`, dry runs at capacities 4 and 7, and `CHUNK_GUARDS`. Chunk responders answer by the chunk text a request carries, so worker-thread order cannot shift which chunk fails. The fake `urlopen` builds an `http.client.HTTPConnection` from the request host, so urllib's host validation runs as in production.

## Reading results

- `FAIL <property>: <case>` is a new violation with its first counterexample. The case string is the input: batch line kinds in order, or the base URL, model, question IDs, record, and key flag. Reproduce it by running `jev.py` with those inputs before calling it a bug.
- A bug in the code makes a property fail on a plausible input. A modeling error makes it fail because the oracle in `check.py` is wrong, for example a fixture serialized differently from what a user would write. Fix the oracle only when the README contract says the code's behavior is correct, and say so in the commit.
- `KNOWN <finding>` is an accepted current violation in `KNOWN_FINDINGS`. `FIXED? <finding>` means it stopped reproducing: confirm the fix, then delete its entry.
- `MUTANT MISSED` means a property can no longer fail on the break it guards. `MUTANT STALE` means the anchor text in `MUTANTS` or `DEMO_MUTANTS` no longer exists in `jev.py` or `scripts/demo_sessions.py`. Update the anchor to the equivalent code; never delete a mutant to get green.
